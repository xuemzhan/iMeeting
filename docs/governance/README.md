# iMeeting 文档规制

生效日期：2026-10-31。此说明随 iMeeting 独立仓库保留，文档导航不依赖外层 FunASR 目录。

## 存放与命名

| 内容 | 位置 |
|---|---|
| 需求与验收标准 | `docs/requirements/REQ-NNN-topic.md` |
| 架构、取舍和重大决策 | `docs/architecture/YYYY-MM-DD-topic.md` |
| 实施任务与依赖 | `docs/plans/YYYY-MM-DD-topic.md` |
| 评审发现与复核 | `docs/reviews/YYYY-MM-DD-topic.md` |
| 阶段结果与测量 | `docs/reports/YYYY-MM-DD-topic.md` |
| 原始测试/扫描/实验材料 | `docs/audits/YYYY-MM-DD/` 或 `benchmarks/<run>/` |

既有文件保留路径，由[文档中心](../README.md)提供分类入口。实验报告保留在数据旁；不复制多份正文。需求索引只负责导航和依赖，阶段结果写入报告。

## 状态、责任与证据

标题下记录编号、类型、文档状态、适用日期、整理日期、责任角色及关联文档。稳定编号使用 `IM-REQ/DES/PLN/REV/RPT/EVD-NNN`；原有 `REQ-001/002` 仍保留在标题与文件名中。

文档状态采用草案、提案、持续维护、阶段快照、历史记录、已被替代。实现进度独立记录：需求已写代码不代表评审通过，能力实现不代表目标服务器上线验收。具体维护人目前待指派，不能把责任角色当成已认领人。

阶段快照保留原日期、环境、模型 revision、语料、测试集合和结论边界。后续结果建新报告并链接，不能覆盖旧数值。标记“已被替代”时必须链接后继文件和替代范围。

新文档至少包含：背景与范围、具体内容、验收或验证、证据、未完成项、关联文档。Plan 需要任务/依赖/责任/完成标准；Review 需要受审版本、问题、严重性、复现及复核；报告需要环境、方法、结果和局限。

## 更新检查

新增或改动时同步[文档中心](../README.md)及所属目录索引。使用 UTF-8/LF、相对链接；保留既有章节锚点。检查链接能定位到文件，代码引用真实存在，命令确实执行后才记为通过；未经复测的历史结果明确标注。

在外层 FunASR 工作区联合维护时，同时更新其项目文档台账并运行文档检查。独立检出 iMeeting 时，至少核验本文与文档中心的全部相对链接；不要求检出外层仓库才能阅读。当前维护工具不自动验证业务代码、模型性能或部署结果。
