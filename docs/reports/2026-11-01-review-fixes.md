# 2026-11-01 全局复核问题修复

> 文档类型：报告；状态：阶段快照；日期：2026-11-01。
> 维护责任：待指派（iMeeting 维护者）。[文档中心](../README.md) · [证据](../reviews/evidence/2026-11-01-review-fixes/README.md)。

本轮按独立复核发现的四项P1问题修复，基线为 `f40385b`，没有修改生产数据、执行部署或变更模板匹配默认开关。[原R6报告](2026-10-31-r6-optimization.md)的历史结果保留；当前修复口径如下。

| 问题 | 根因 | 修复与回归 |
|---|---|---|
| 自动重放修改已确认模板 | 按来源找到模板后直接更新贡献，绕过确认保护 | 自动重放不改已确认来源；相同向量直接返回，变化向量使用稳定候选来源键，进入本场未确认模板；重复候选不新增。明确人工确认仍可写入 |
| 会议清理外键错误 | 直接删除临时声纹，没有处理模板/来源/冲突；人员关系等新增子表也未纳入 | 临时声纹复用统一依赖清理服务；清理参会关系和说话人角色。人员属性保留，但将已删除来源会议置空，避免丢失跨会议知识 |
| 推理持有SQLite写锁 | 每提取一段就写缓存并flush，下一段模型推理仍在同一写事务内 | 当前说话人的全部音频解码/向量提取结束后，才批量写入缓存并处理模板；仍按说话人提交。回归在每次模型调用期间用独立连接申请写锁，必须全部成功 |
| 模型版本变化仍命中旧缓存 | 持久缓存键只有模型名，与运行时模型加载签名不一致 | 复用 `speaker.embedding_model_signature()`，包含实际模型名、hub、revision和更新策略；三种配置变化分别测试失效 |

主要实现：[模板和取样](../../backend/src/imeeting/engine/voice_template.py)、[会议清理](../../backend/src/imeeting/meeting_cleanup.py)。常规回归：[test_review_followup_fixes.py](../../backend/tests/test_review_followup_fixes.py)。

变化后的自动证据不会覆盖已确认模板，仍受原有五槽上限与正式模板保护；槽满且没有可用候选槽时显式失败，不静默淘汰正式样本。该修复没有增加新的确认交互或改变人工决定协议。缓存在配置签名变化后自然失效，不需要迁移数据库；代价是首次重新提取。

推理阶段不申请写锁，缓存和模板落库阶段仍需短暂写锁；这不是多实例并发或所有后台任务的无锁承诺。每位说话人的取样向量临时缓存在内存中，数量仍受已有取样上限约束。没有测量新的真实模型延迟或识别准确率。

验证结果以[本轮证据](../reviews/evidence/2026-11-01-review-fixes/README.md)为准。完整后端回归728项通过、0失败（490.84秒）；新增六项均包含其中，不与定向运行重复累加。Ruff及差异空白检查通过。前端未改动，不重复计入历史浏览器结果；真实CAM++、供应商LLM、目标服务器、Docker/TLS与长稳未重新验收。
