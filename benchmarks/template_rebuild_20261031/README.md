本目录保存 R6「取样嵌入缓存 / 细粒度进度 / 先筛后算」的同机对照材料：测量脚本、原始 JSON 与环境说明。数字只对本机、本参数与合成输入成立。

## 口径与边界

- 环境：Windows 11（10.0.26200）、Python 3.14.3、numpy 2.5.4、16 逻辑核、`ASR_MODE=off`。
- 声纹模型不可用（本机没有 torch，CAM++ 加载不了）：`extract_embedding` 用确定性替身，因此**单条向量的模型推理耗时没有测到**；下表的重建耗时只覆盖「解码 + 取样 + 聚类 + 落库」。
- 重建使用真实 SQLite 与真实 WAV（16 kHz 单声道，按片段边界切片），不是真实会议录音。
- 匹配是纯 numpy 路径（`voice_template.templates_matrix` + `voice_match.match`），不含网络与模型开销。
- 每个配置只跑一次。单次抖动在重建 0.1–0.2 s、匹配尾部 10–30% 量级；同一配置连跑两次实测「缓存重复重建」在 0.19–0.26 s 波动，不要按小数点后三位引用。
- 测量期间没有其他重负载进程（并行跑测试会明显抬高本表数值，实测过一轮约 +60%）。

## 结果（2026-10-31T22:15:02+0800）

### 重建：4 位说话人 × 32 段，每轮 128 条取样

| 运行 | 墙钟(s) | 解码次数 | 缓存命中 | 模板 |
|---|---:|---:|---:|---|
| 缓存关闭（首次，建 20 条模板） | 0.652 | 128 | 0 | created 20 |
| 缓存关闭（重复，仅更新） | 0.222 | 128 | 0 | updated 20 |
| 缓存开启（首次，填充缓存） | 0.319 | 128 | 0 | updated 20 |
| 缓存开启（重复，全部命中） | 0.173 | 0 | 128 | updated 20 |

- 可比的是「缓存关闭（重复）」与「缓存开启（重复）」两行：128 次逐段解码被完全消掉，墙钟 0.222 → 0.173 s。
- 解码本身在合成音频上只占约 0.05 s；真实会议的主要成本是每条的 CAM++ 推理，本机没有模型，不能把这个比例外推到生产。
- 缓存行数 128（每个片段一行），数据库 2.69 MB（含 WAL）。

### 匹配：1980 条活跃模板

| 项目 | 平均 | p95 | p99 |
|---|---:|---:|---:|
| 场景粗筛掩码（旧：逐行 Python `match_score`） | 1.977 ms | 2.171 | 2.293 |
| 场景粗筛掩码（新：整型编码向量化） | 0.059 ms | 0.090 | 0.121 |
| 端到端匹配，粗筛开启（候选占比 41.67%） | 0.680 ms | 0.828 | 1.004 |
| 端到端匹配，全矩阵 | 1.591 ms | 2.037 | 2.515 |

- 矩阵冷加载（1980 条）104.047 ms，只在缓存过期或失效时发生。
- 200 次查询都是随机向量，命中数为 0；比较的是「一次匹配调用」的耗时，不是识别准确率。
- 粗筛只有在「行数 × 场景维度」都大到超过向量化开销时才净赚；脚本输出 `prefilter_eligible_ratio`，候选占比接近 100% 时它与全矩阵基本同价。

## 复现

在 `iMeeting/` 目录执行：

```powershell
$env:PYTHONUTF8='1'
.\.venv-production-review\Scripts\python.exe benchmarks\template_rebuild_20261031\bench_template_optimization.py --speakers 4 --segments-per-speaker 32 --templates 2000 --queries 200 --out benchmarks/template_rebuild_20261031/results-20261031.json
```

脚本每次在 `_run/run_<时间戳>/` 下新建临时数据库与 WAV，不删除历史目录；`_run/` 已在 `.gitignore` 中排除。原始输出见 [results-20261031.json](results-20261031.json)。
